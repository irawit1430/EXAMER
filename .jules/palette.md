
## 2024-04-25 - Icon-only Buttons and Default Focus Styles
**Learning:** In the `examer` design system, the default `<button>` component and raw HTML buttons (like the `Modal` and `Sidebar` close buttons) lack inherent keyboard `focus-visible` styles. Furthermore, icon-only buttons often omit the essential `aria-label` attribute, making them completely inaccessible to screen readers.
**Action:** Always append `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-primary` to any interactive element that lacks a focus state, and explicitly add `aria-label` attributes to any button where the child content is purely decorative or an icon component (e.g., `<X />`).
## 2024-04-25 - MentorMessage Interactive Elements Accessibility
**Learning:** For interactive components like concept explanations and feedback cards that toggle dynamically revealed content in `MentorMessage.tsx`, standard practice in this application is to use `aria-expanded` on the toggle button and wrap the `<AnimatePresence>` component with a `<div aria-live="polite">` container to ensure screen readers reliably announce the content despite unmounting. For interactive quiz options, `aria-pressed` should be used to communicate state.
**Action:** Always wrap `<AnimatePresence>` dynamic content with `aria-live="polite"` and explicitly set `aria-expanded`/`aria-pressed` on their corresponding control buttons.
