
## 2024-04-25 - Icon-only Buttons and Default Focus Styles
**Learning:** In the `examer` design system, the default `<button>` component and raw HTML buttons (like the `Modal` and `Sidebar` close buttons) lack inherent keyboard `focus-visible` styles. Furthermore, icon-only buttons often omit the essential `aria-label` attribute, making them completely inaccessible to screen readers.
**Action:** Always append `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-primary` to any interactive element that lacks a focus state, and explicitly add `aria-label` attributes to any button where the child content is purely decorative or an icon component (e.g., `<X />`).
## 2025-02-24 - Dynamic Content and ARIA Regions
**Learning:** When using `AnimatePresence` to conditionally render dynamically revealed content (like explanations or feedback), the wrapper needs an `aria-live="polite"` attribute so screen readers announce it. Crucially, this wrapper must be placed *outside* the `AnimatePresence` component to guarantee screen reader reliability, otherwise the region itself mounts/unmounts dynamically, which screen readers often ignore.
**Action:** Wrap dynamically revealed text with `<div aria-live="polite">` as the parent containing the conditional logic or `AnimatePresence` component. Additionally, ensure toggleable options communicate their state to screen readers using `aria-pressed` (for multi-select or single-select options like MCQs) or `aria-expanded` (for reveals like Concept Cards).
