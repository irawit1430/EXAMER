
## 2024-04-25 - Icon-only Buttons and Default Focus Styles
**Learning:** In the `examer` design system, the default `<button>` component and raw HTML buttons (like the `Modal` and `Sidebar` close buttons) lack inherent keyboard `focus-visible` styles. Furthermore, icon-only buttons often omit the essential `aria-label` attribute, making them completely inaccessible to screen readers.
**Action:** Always append `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-primary` to any interactive element that lacks a focus state, and explicitly add `aria-label` attributes to any button where the child content is purely decorative or an icon component (e.g., `<X />`).
## 2024-05-19 - Screen reader support for Framer Motion's AnimatePresence
**Learning:** When using Framer Motion's `AnimatePresence` to dynamically mount or unmount content (like explanations or feedback), screen readers may fail to announce the newly revealed content if the `aria-live` region is directly inside the unmounted component. The `aria-live="polite"` container must be placed *outside* the `AnimatePresence` to persist in the DOM, allowing it to reliably detect and announce the inner DOM additions.
**Action:** Always wrap `AnimatePresence` blocks with `<div aria-live="polite">` when the revealed content needs to be announced by screen readers, such as form feedback, quiz explanations, or dynamic alerts.
