## 2024-11-20 - Prevent component re-renders from high-frequency Zustand store updates
**Learning:** Destructuring a Zustand store object (e.g., `const { prop1, prop2 } = useStore()`) subscribes the component to ALL store changes. In this codebase, the `useMentorStore` receives frequent chunk updates during AI streaming (modifying `streamBuffer`), which causes severe re-render bottlenecks in components like `GlobalMentor` and `StudyMentorPanel` if the store is destructured.
**Action:** Always use fine-grained individual selectors (e.g., `const prop1 = useStore((s) => s.prop1); const prop2 = useStore((s) => s.prop2);`) for Zustand stores, especially when those stores handle high-frequency updates like streaming data or real-time progress. Avoid object destructuring entirely for Zustand hooks.
